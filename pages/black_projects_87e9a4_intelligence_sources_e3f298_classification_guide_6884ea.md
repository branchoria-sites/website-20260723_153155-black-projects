## Introduction

Security classification guides are the practical rulebooks that translate broad secrecy decisions into day-to-day instructions. Rather than simply stating that an intelligence programme or black project is classified, they specify exactly which facts, technical details, operational relationships and timelines require protection, at what level, and for how long. This matters because intelligence programmes are often compromised not by one dramatic disclosure but by the accumulation of seemingly harmless pieces of information. Modern classification policy therefore treats some *combinations* of facts as more sensitive than the individual facts themselves. Executive Order 13526 requires agencies with original classification authority to create and maintain classification guides so that everyone handling programme information applies the same decisions consistently rather than making ad hoc judgements.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.presidency.ucsb.edu/documents/executive-order-13526-classified-national-security-information" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: presidency.ucsb.edu">[The American Presidency Project]</a><span class="citation-popover" role="note"><span class="citation-popover-source">presidency.ucsb.edu</span><span class="citation-popover-title">executive order 13526 classified national security information</span><span class="citation-popover-snippet">The American Presidency ProjectExecutive Order 13526—Classified National Security Information &#124; The American Presidency ProjectDecember 2...</span></span></span>

Within intelligence and defence programmes, these guides are especially important because adversaries routinely analyse procurement records, personnel movements, technical publications, satellite imagery and public statements to reconstruct hidden capabilities. Classification guides seek to prevent that reconstruction by identifying not only sensitive facts, but also sensitive associations.

## Who decides which programme details stay secret?

Classification guides originate from officials who possess original classification authority and have responsibility for the programme or subject area concerned. Under Executive Order 13526, each guide must be personally approved by an authorised official and must identify the specific elements of information that require classification, together with the appropriate classification level and duration. Agencies must also review and update guides as programmes evolve.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.presidency.ucsb.edu/documents/executive-order-13526-classified-national-security-information" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: presidency.ucsb.edu">[The American Presidency Project]</a><span class="citation-popover" role="note"><span class="citation-popover-source">presidency.ucsb.edu</span><span class="citation-popover-title">executive order 13526 classified national security information</span><span class="citation-popover-snippet">The American Presidency ProjectExecutive Order 13526—Classified National Security Information &#124; The American Presidency ProjectDecember 2...</span></span></span>

In practice, this means a guide does far more than declare an entire programme "Secret" or "Top Secret". Instead, it breaks the programme into discrete categories such as:

## How programme facts receive levels and durations

Classification guides support what is known as **derivative classification**. Most officials handling classified information do not make original secrecy decisions themselves. Instead, they consult an approved guide and apply the prescribed markings to reports, emails, presentations and databases.

A typical guide specifies:


<div class="content-enhancement content-enhancement--insight-grid" markdown="1">

* **Exactly which information elements are classified.**<span class="citation-chip-wrap"><a class="citation-chip" href="https://www.presidency.ucsb.edu/node/287521" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: presidency.ucsb.edu">[presidency.ucsb.edu]</a><span class="citation-popover" role="note"><span class="citation-popover-source">presidency.ucsb.edu</span><span class="citation-popover-snippet">Source details in endnotes.</span></span></span>
* **The classification level for each element.**
* **The reason the information is protected.**
* **How long protection normally lasts.**
* **Whether special exemptions from automatic declassification apply.**

</div>

Executive Order 13526 generally limits derivative classification to the duration established by the original guidance, with most classified information subject to review by the 25-year point unless recognised exemptions apply, such as protection of [intelligence sources]({{ 'intelligence-sources/' | relative_url }}) or particularly sensitive weapons design information.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.presidency.ucsb.edu/documents/executive-order-13526-classified-national-security-information" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: presidency.ucsb.edu">[The American Presidency Project]</a><span class="citation-popover" role="note"><span class="citation-popover-source">presidency.ucsb.edu</span><span class="citation-popover-title">executive order 13526 classified national security information</span><span class="citation-popover-snippet">The American Presidency ProjectExecutive Order 13526—Classified National Security Information &#124; The American Presidency ProjectDecember 2...</span></span></span>

This structured approach reduces arbitrary decisions while ensuring that programme participants working in different agencies or contractor organisations follow the same rules.

## Why associations and combinations may be classified

One of the most important features of modern classification guidance is its treatment of **compilations** and **associations**.

A single procurement contract may reveal little. A publicly visible construction project may appear routine. A conference presentation discussing an unusual sensor technology may also seem harmless. However, when those three facts are connected, they may reveal the existence, location or purpose of a previously concealed intelligence capability.

This reflects the long-recognised **mosaic effect**: adversaries often derive valuable intelligence by assembling numerous fragments that are individually unclassified or only mildly sensitive.

Executive Order 13526 formally defines a compilation as an aggregation of previously unclassified information, while government guidance explains that such compilations may require an original classification decision if their combined meaning [reveals]({{ 'reveals/' | relative_url }}) protected national security information.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.presidency.ucsb.edu/documents/executive-order-13526-classified-national-security-information" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: presidency.ucsb.edu">[The American Presidency Project]</a><span class="citation-popover" role="note"><span class="citation-popover-source">presidency.ucsb.edu</span><span class="citation-popover-title">executive order 13526 classified national security information</span><span class="citation-popover-snippet">The American Presidency ProjectExecutive Order 13526—Classified National Security Information &#124; The American Presidency ProjectDecember 2...</span></span></span>

Accordingly, security classification guides frequently identify combinations such as:


<div class="content-enhancement content-enhancement--metric" markdown="1">

* Technical specifications linked to a named facility.
* Sensor performance connected to deployment timing.
* Operational plans associated with particular communications systems.
* Personnel identities combined with mission assignments.
* Procurement data linked to classified capabilities.

</div>

These combinations may require a higher classification level than any individual component because the association exposes information that would otherwise remain concealed.

## How guides anticipate reconstruction by adversaries

Classification guides are designed around realistic intelligence analysis rather than isolated documents.

Instead of asking, "Is this sentence classified?", guide authors increasingly ask, "What could an informed foreign analyst infer if this information were combined with material already available?"

That perspective explains why guides sometimes protect relationships between otherwise ordinary facts, including:

* Which contractor develops which subsystem.
* Which test range supports a particular aircraft.
* Which communications architecture accompanies a specific sensor.
* Which [maintenance]({{ 'maintenance/' | relative_url }}) activity coincides with deployment cycles.

The concern is not necessarily that each fact is inherently secret, but that together they reveal programme architecture, operational readiness or intelligence collection methods.

Department of Defense classification policy explicitly requires original classification authorities to identify known combinations of otherwise unclassified data that become classified when aggregated and to record those combinations in security classification guides.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.dodig.mil/Portals/48/Documents/Policy/520001_vol1.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: dodig.mil">[dodig.mil]</a><span class="citation-popover" role="note"><span class="citation-popover-source">dodig.mil</span><span class="citation-popover-title">520001 vol1</span><span class="citation-popover-snippet">DoD 5200.01, Vol. 1, February 24, 2012March 7, 2012...</span><span class="citation-popover-meta">Published: February 24, 2012</span></span></span>

## Why consistency matters across agencies and contractors

Large intelligence and defence programmes often involve multiple military commands, civilian agencies, laboratories and private [contractors]({{ 'contractors/' | relative_url }}). Without common guidance, one organisation might classify a document while another releases substantially similar information.

Classification guides reduce this risk by providing a common reference for everyone authorised to handle programme information.

The benefits include:


<div class="content-enhancement content-enhancement--metric" markdown="1">

* Uniform document markings.
* Consistent treatment of technical data.
* Predictable information sharing within authorised communities.
* Reduced accidental disclosure.

## The risks of inconsistency, excessive secrecy and outdated guidance

Although classification guides improve consistency, they also present governance challenges.

If guides are not regularly reviewed, they may continue protecting information long after the original security justification has weakened. Programmes evolve, technologies become obsolete, and capabilities may enter public knowledge through authorised releases. Outdated guidance can therefore contribute to unnecessary [overclassification]({{ 'trust/' | relative_url }}).

Conversely, incomplete guides can leave genuine vulnerabilities unprotected if new operational practices or technologies emerge faster than the guidance is revised.

Government policy addresses these risks by requiring periodic review and timely incorporation of new original classification decisions into existing guides. Agencies also maintain formal procedures for challenging questionable classification decisions and updating guidance when circumstances change.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.presidency.ucsb.edu/documents/executive-order-13526-classified-national-security-information" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: presidency.ucsb.edu">[ucsb.edu]</a><span class="citation-popover" role="note"><span class="citation-popover-source">presidency.ucsb.edu</span><span class="citation-popover-title">executive order 13526 classified national security information</span><span class="citation-popover-snippet">The American Presidency ProjectExecutive Order 13526—Classified National Security Information &#124; The American Presidency ProjectDecember 2...</span></span></span>

Academic research examining large collections of [declassified]({{ 'declassified/' | relative_url }}) government records likewise suggests that classification decisions are not perfectly consistent across officials, reinforcing the importance of structured guidance while also highlighting continuing concerns about both overclassification and underclassification.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://arxiv.org/abs/1611.00356" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: arxiv.org">[arXiv]</a><span class="citation-popover" role="note"><span class="citation-popover-source">arxiv.org</span><span class="citation-popover-title">arXiv Using Artificial Intelligence to Identify State Secrets</span><span class="citation-popover-snippet">Using Artificial Intelligence to Identify State SecretsNovember 1, 2016...</span><span class="citation-popover-meta">Published: November 1, 2016</span></span></span>

## Why classification guides remain central to protecting intelligence methods

For intelligence programmes and [black projects]({{ 'black-projects/' | relative_url }}), the most sensitive secret is often not a single document but the hidden relationship between many ordinary-looking facts. Security classification guides are designed to identify those relationships before they appear in reports, databases or public records.

By specifying which combinations of information reveal intelligence sources, collection methods, operational capabilities or programme existence, the guides translate broad national security policy into practical decisions that thousands of authorised personnel can apply consistently. Their effectiveness therefore depends not only on protecting individual secrets, but also on recognising how apparently routine details can become strategically significant when viewed together.

      try { if (window.localStorage) localStorage.setItem('phoenix-ebay-market', marketId); } catch (err) {}
    }
    closeMenu(section);
  }
  sections.forEach(function (section) {
    if (section.getAttribute('data-ebay-localized-init') === '1') return;
    section.setAttribute('data-ebay-localized-init', '1');
    var available = availableMarkets(section);
    var marketId = defaultMarket;
    if (window.PhoenixAffiliateLocation && window.PhoenixAffiliateLocation.inferMarket) {
      marketId = window.PhoenixAffiliateLocation.inferMarket(available, {
        storageKey: 'phoenix-ebay-market',
        defaultMarket: defaultMarket
      });
    } else if (available.indexOf(defaultMarket)< 0) {
      marketId = available[0] || defaultMarket;
    }
    var select = section.querySelector('[data-ebay-market-select]');
    if (select) {
      select.addEventListener('change', function () {
        applyMarket(section, select.value, true);
      });
    }
    var trigger = section.querySelector('[data-ebay-market-trigger]');
    var menu = section.querySelector('[data-ebay-market-menu]');
    if (trigger && menu) {
      trigger.addEventListener('click', function (event) {
        event.stopPropagation();
        var expanded = trigger.getAttribute('aria-expanded') === 'true';
        menu.hidden = expanded;
        trigger.setAttribute('aria-expanded', expanded ? 'false' : 'true');
        var picker = trigger.closest('.fr-ebay-market-picker');
        if (picker) picker.classList.toggle('fr-ebay-market-picker--open', !expanded);
      });
      Array.prototype.slice.call(menu.querySelectorAll('[data-ebay-market-option]')).forEach(function (button) {
        button.addEventListener('click', function (event) {
          event.stopPropagation();
          applyMarket(section, button.getAttribute('data-ebay-market-option'), true);
        });
      });
      document.addEventListener('click', function () { closeMenu(section); });
    }
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-button]')).forEach(function (button) {
      button.addEventListener('click', function () {
        applyMarket(section, button.getAttribute('data-ebay-market-button'), true);
      });
    });
    applyMarket(section, marketId, false);
  });
})();
